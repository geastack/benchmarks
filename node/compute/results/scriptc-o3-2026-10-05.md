# scriptc 0.2.3: O2 versus O3 — 2026-10-05

Same Linux dedicated Linux benchmark host host, fixtures, iteration counts and CPU 0 pinning as the previous compute run. Both variants use the scriptc 0.2.3 bundled LLVM helper, with identical emitted LLVM and identical shipped release runtime objects. Only helper --opt-level changes from 2 to 3. External linking follows scriptc's native-link-info recipe, including target, runtime objects, system libraries and driver flags. Binaries are stripped. This is a manual helper experiment: the public CLI exposes release (O2) or dev, not O3. The precompiled runtime is unchanged and is not rebuilt at O3. No march=native setting is added.

Five fresh-process samples per successful variant, alternating O2/O3 order. Reported time is the best inner workload time; every sample matches the prior Node output. All 27 fixtures were attempted. Prime sieve was tested only at O3 because O2 already timed out in the prior run; O3 also timed out at 180 seconds, exit 124. It is excluded from ratios. 26 other fixtures completed correctly at both levels.

Geometric-mean O2/O3 speedup: **1.0072×**, or **0.72%**. Compared with the earlier Gea O3 measurements, scriptc O3 remains **6.48× slower** across the same 26 fixtures. The latter comparison reuses prior Gea timings and was not a new simultaneous Gea run.
