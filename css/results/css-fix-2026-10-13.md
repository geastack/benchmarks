# CSS engine: css-fix against main, 2026-10-13

Desktop comparison of [geastack/core#59](https://github.com/geastack/core/pull/59) (`css-fix`, rebased on main) with `main`, using `css/desktop/compare-css-performance.mjs` on all 30 cases of [the catalog](../shared/catalog.json). Each value is the median frame work time of 7 rounds × 240 frames after 60 warmup frames, averaged over two runs; base and candidate alternate between rounds. These are native desktop CPU/raster timings, not device FPS.

css-fix is faster in 25 cases, within ±2% in 2 (sticky-scroll-96, sticky-sections-96) and slower in 3 (blend-mode-24, multicol-3, blend-modes-15). All 3 slower cases draw a feature main does not implement: main skips the blend and the column layout, so its time is not for the same output. Over the 19 cases where both draw identical pixels, css-fix takes 3206 µs against 11375 µs (−71.8%; geometric mean 2.21×).

## Status

Every case finished and passed its own checks (layout, selection, text, scroll movement, momentum) on both refs. 19 cases end on identical pixel and geometry hashes in both timing runs and in `--verify-only`. The other 11 differ because css-fix draws something main does not:

| case | why the output differs |
| --- | --- |
| rounded-scroll | css-fix clips the scrolled rows to the rounded padding box; main paints square corners |
| minimal-text-12 | css-fix draws bare flex text on its baseline instead of centring it |
| border-image-24 | main does not support border-image |
| blend-mode-24 | main does not support background-blend-mode |
| multicol-3 | main does not lay out columns |
| line-clamp-24 | main does not support line-clamp |
| text-emphasis-24 | main does not support text-emphasis |
| sticky-scroll-96 | main does not support position: sticky |
| blend-modes-15 | main does not support background-blend-mode |
| rounded-update-96 | css-fix clips the updated rows to the rounded padding box; main paints square corners |
| sticky-sections-96 | main does not support position: sticky |

Final hashes do not prove that a scroll moved on screen. For rounded-scroll the final-frame hashes were also compared after 32, 48, 64 and 96 frames. On css-fix the pixel hash differs at every count and repeats exactly where the geometry repeats (32 and 96), so the rows move under the rounded clip. On main it also changes, but 48 and 64 frames end on the same pixels with different geometry.

## Feature-stripped builds

Apps are built with the CSS families their sources use; the analyzer reports them and the CLI turns the rest off. `--minimal` applies the box profile's defines to both refs and times the box cases (average of two runs, after a first run right after the build was discarded):

| case | main | css-fix | change | output |
| --- | ---: | ---: | ---: | --- |
| minimal-box-1 | 19.9 | 19.3 | −2.9% | same |
| minimal-boxes-4 | 26.2 | 22.8 | −13.3% | same |

Native storage from `css/desktop/check-feature-profiles.mjs` (bytes; node / ComputedStyle / RareStyle):

| profile | main | css-fix | css-fix, new families off |
| --- | --- | --- | --- |
| full | 344 / 168 / 344 | 368 / 176 / 364 | |
| box | 72 / 16 / 1 | 104 / 32 / 14 | 80 / 22 / 1 |
| flex | 76 / 20 / 1 | 104 / 32 / 14 | 84 / 24 / 1 |
| complex | 200 / 34 / 264 | 228 / 44 / 276 | 208 / 36 / 264 |

css-fix adds eight families (`GEA_CSS_BACKGROUND_BLEND`, `BORDER_IMAGE`, `LARGE_BOXES`, `LINE_CLAMP`, `MULTICOL`, `SHAPED_CLIPS`, `STICKY`, `TEXT_EMPHASIS`), each default on. The analyzer and CLI do not report or map them yet, so a box app keeps all of them: its node grows from 72 to 104 bytes. The last column compiles the same probe with the profile's defines plus those eight set to 0, which is what mapping them would give; the remaining 8 bytes of node and 6 of style are css-fix fields that no family covers. The box app is still faster on css-fix, as the timing above shows.
